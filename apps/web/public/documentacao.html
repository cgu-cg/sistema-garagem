1. Visão Geral e Arquitetura

O **Sistema Garagem** foi desenvolvido para o gerenciamento interno de operações de garagem de ônibus, focando no registro e controle de abastecimentos de combustível e solturas (despacho) de veículos.

O projeto está estruturado como um **Monorepo** utilizando **NPM Workspaces**, composto por duas aplicações principais localizadas em apps/:

Backend (apps/api)

API REST em **Node.js** com **Express** e **TypeScript**, usando **Prisma ORM** e conectando-se a um banco de dados **PostgreSQL** e **SQL Server**.

Frontend (apps/web)

SPA moderna construída em **React**, **Vite** e **TypeScript**, com design responsivo em **Tailwind CSS**, componentes **Radix UI** e Zustand.

2. Modelagem do Banco de Dados

A estrutura relacional das tabelas gerenciadas pelo Prisma ORM no PostgreSQL é composta da seguinte forma:

// Principais Modelos Relacionados
model User { id Int @id, name String, role String, ... }
model Bus { id Int @id, plate String, prefix String, ... }
model Abastecimento { id Int @id, litersT1 Decimal, fotoT1 String, litersT2 Decimal, fotoT2 String, userId Int, ... }
model Soltura { id Int @id, busId Int, programmedBusId Int, linha String, tabela String, ... }

Tabelas e Campos:

  • users: Armazena credenciais e perfis (roles) de acesso de colaboradores e administradores.
  • buses: Frota de ônibus cadastrada com prefixo, placa e modelo.
  • abastecimentos: Registro de combustíveis independente por tanque (T1 e T2) e caminhos de arquivos das fotos no disco.
  • solturas: Registros de despacho físico contendo linha, tabela, horários programados/reais, código de motorista e observações.

3. Controle de Acesso e Permissões (RBAC)

A visualização de dados e rotas no sistema é estritamente regulada conforme o papel do colaborador logado:

Perfil Descrição Acesso às Funcionalidades
ADMIN Administrador Acesso completo (usuários, frotas, abastecimentos, solturas e auditoria de catracas).
COLABORADOR_ABASTECIMENTO Operador de Bomba Visualização restrita da Dashboard e acesso apenas à tela de Abastecimento.
COLABORADOR_SOLTURA Fiscal de Pista Visualização restrita da Dashboard e acesso apenas à tela de Solturas.
COLABORADOR Visualizador Geral Acesso apenas aos painéis gerais e leitura de métricas básicas da dashboard.

4. Detalhamento Técnico do Backend

A API expõe rotas seguras com criptografia bcrypt de senhas e autenticação via Token JWT com expiração padrão de 8 horas.

  • POST /api/auth/login: Login de usuários.
  • GET /api/buses: Listagem de frota.
  • POST /api/abastecimentos: Cadastro de consumo de combustível com webcams.
  • POST /api/solturas: Registro de saídas operacionais.

5. Detalhamento Técnico do Frontend

O aplicativo do cliente React é projetado com estética rica e suporte completo a Light/Dark Mode reativo salvando escolhas do usuário no localStorage.

Páginas Principais:

  • Dashboard: Gráficos de consumo e barras de progresso adaptáveis.
  • Controle de Câmeras: Validação segura de dispositivos de mídia para registrar abastecimentos com fotos.
  • Catracas (ADMIN): Painel avançado integrado ao SQL Server e PDF de diários de bordo operacionais.

6. Infraestrutura e Docker

O projeto utiliza Docker Compose para subir localmente e em produção todas as aplicações de forma encapsulada:

  • Banco: PostgreSQL 16.
  • API: Node Alpine com Prisma Client.
  • Frontend: Build otimizada com Vite servida pelo proxy reverso Nginx.

7. Como Executar o Projeto

Passo 2: Configurar variáveis e rodar migrations

cp .env.example .env
npm run db:migrate

Passo 3: Executar ambiente dev

9. Roteiro de Deploy (Servidor Linux)

Siga o sequenciamento prático abaixo para aplicar atualizações locais no servidor de produção da empresa:

1. Enviar arquivos atualizados via Rsync

Exclui pastas de controle de versão e dependências locais:

rsync -avz --exclude 'node_modules' --exclude '.git' --exclude 'build' --exclude 'dist' ./ validasic@192.168.0.52:~/sistema-garagem

2. Conectar e derrubar containers de produção

sudo docker-compose down

3. Recompilar e iniciar containers atualizados

sudo docker-compose up -d --build

4. Aplicar migrations de banco

sudo docker-compose exec api npx prisma migrate deploy
